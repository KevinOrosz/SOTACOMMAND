# {{PLUGIN_NAME}}

The SOTACOMMAND engine as a Claude Code plugin. Each role is a subagent whose boundaries are enforced by its tool policy, a protected-path hook and, for roles that change code, a git worktree. Hooks run the session ritual, and a workflow runs the convergence protocol.

Everything in this directory is generated by `adapters/generate.py` from the role sources and `adapters/templates/engine/`. Edit those, then regenerate. `python3 adapters/generate.py --check` fails when a file here was edited by hand.

## Install

From the repository's marketplace:

```sh
claude plugin marketplace add KevinOrosz/SOTACOMMAND
claude plugin install {{PLUGIN_NAME}}@{{MARKETPLACE_NAME}}
```

For a single session from a checkout: `claude --plugin-dir engine`.

## What loads

| Component | File | Effect |
|---|---|---|
| Main agent | `settings.json` | The session runs as `{{MAIN_ROLE}}` |
| Agents | `agents/*.md` | One subagent per role, each with `model: inherit` |
| SessionStart hook | `hooks/hooks.json` → `tools/session_open.py` | Reports memory-file sizes against their caps |
| PreToolUse hook | `hooks/hooks.json` → `tools/protect_paths.py` | Denies Write and Edit calls on protected paths and outside a role's write scope |
| UserPromptSubmit hook, and every hook above and below | `tools/ledger.py` | Counts sessions, the owner's messages (length only), refusals, approvals asked and failed closes in a local file, `.sotacommand/ledger.jsonl`. The owner-auditor reports from these counts. |
| Recall | `tools/recall.py` | Session start keeps each changed handoff in `.sotacommand/history/`; `recall.py "<words>"` ranks passages from the history, `memory/`, the owner profile and the team card. |
| Learning loop | `tools/skill_loop.py` | `draft` turns an owner-approved proposal into an experimental project skill; `status` measures it from the ledger; `promote` marks it stable only when the problem it targets has stopped. |
| PreToolUse hook | `hooks/hooks.json` → `tools/protect_team.py` | Refuses to hand work to a helper the owner turned off in the interview (`profile/answers.json`). |
| PreToolUse hook | `hooks/hooks.json` → `tools/protect_shell.py` | Applies the same rules to Bash and PowerShell commands, plus `shell_guard` deny and ask patterns. A guard, not a sandbox. |
| Stop hook | `hooks/hooks.json` → `tools/session_close_gate.py` | Keeps Claude working while the configured verify command fails |
| Workflow | `workflows/convergence.js` | `/{{PLUGIN_NAME}}:convergence`: independent passes, then one synthesizer |
| Skill | `skills/os-boot/` | The boot protocol, since a plugin `CLAUDE.md` is never loaded |
| Skill | `skills/wizard/` | `WIZARD`: setup, health check and a tour of the team |
| Templates | `templates/` | `os.config.json` and T1 memory files to copy into a project |

## Requirements

The hook tools need `python3` (3.9 or later) on `PATH` and use only the standard library. If the protected-path hook cannot run, Claude Code blocks the write (`onFailure: block`), so the boundary fails closed.

## Project files

Copy `templates/os.config.json` to the project root, and each `templates/memory/<name>.template.md` to `memory/<name>.md`. The keys are described in `skills/os-boot/references/os-config.md`.
